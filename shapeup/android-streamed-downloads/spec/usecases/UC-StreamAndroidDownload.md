# Use Case: StreamAndroidDownload

## Summary
The system (`SimpleSessionProvider.dataTask`, called internally by `writeTemp` and
`prepareSourceMedia`) streams an Android download's origin response directly to disk through a
native OkHttp/Okio path, using bounded memory regardless of file size, instead of `blob-util`'s
defective in-memory buffering.

## Preconditions
- Caller invokes `dataTask(url, opts, cb)` with `opts.fileCache === true` and a non-empty
  `opts.path` (the exact shape both `writeTemp`'s non-Android branch and `prepareSourceMedia`
  already send today).
- `Platform.OS === 'android'`.

## Input

```typescript
interface StreamAndroidDownloadInput {
  url: string;
  headers?: Record<string, string>;   // forwarded verbatim, incl. Range for byte-range requests
  destPath: string;                   // opts.path — the temp file path the caller already owns
  requestId: string;                  // generated by A3's wrapper, same key space as NanoHTTPD's
}
```

## Steps

```
1. A3 (`SimpleSessionProvider.dataTask`'s Android branch) detects `{fileCache: true, path}` and
   generates a `requestId`, instead of calling `RNFetchBlob.config(...).fetch(...)`.
2. A3 calls the native `downloadToFile(url, headersJson, destPath, requestId)` TurboModule
   method and wraps the result into a `StatefulPromise<FetchBlobResponse>`.
3. A1 (native) opens an OkHttp request with the forwarded headers, tracks the `Call` under
   `requestId`, and begins streaming the response body straight to `destPath` via Okio's file
   sink (constant-size buffer — INV-02).
4. On stream completion, A1 resolves a JSON-encoded `{status, headers, contentLength,
   contentRange}` result (per [[contracts/android-download-transport.contract]]).
5. A3's wrapper parses that JSON and resolves the `StatefulPromise` with a `FetchBlobResponse`
   shape identical to what `blob-util`'s `fileCache` mode already returns — `respInfo.status`,
   `respInfo.headers`, `.cancel()` all present (RULE-02).
6. The caller (`writeTemp` or `prepareSourceMedia`) proceeds exactly as it does today —
   `verifyAndPromote`/`discardTemp` (unchanged, out of this UC's scope) decide promote vs
   discard from the resolved `respInfo` (R3).
```

## Output

```typescript
interface StreamAndroidDownloadOutput {
  data: undefined;          // fileCache mode never returns base64 data
  path: string;              // === destPath
  respInfo: {
    status: number;
    headers: Record<string, string>;
  };
}
```

## System Flow

```
[writeTemp / prepareSourceMedia: dataTask(url, {fileCache:true, path}, cb)]
  → [SimpleSessionProvider.dataTask: Android branch (A3)]
    → [Native: CacheVideoHttpProxyModule.downloadToFile (A1)]
      → [OkHttp Call streams response → Okio file sink → destPath]
      ← [JSON result: {status, headers, contentLength, contentRange}]
    ← [A3 wrapper: StatefulPromise<FetchBlobResponse> resolved]
  ← [caller: verifyAndPromote / discardTemp — unchanged, downstream]
```

## Invariants
- [INV-01] `AndroidDownloadTask.status` only transitions `pending → streaming →
  (completed | failed | cancelled)` — see [[domain-model#Aggregate-AndroidDownloadTask]].
- [INV-02] Memory used while `status = streaming` is bounded by a fixed buffer, never
  proportional to `Content-Length` (the R8 claim).
- [INV-03] `ResponseBody`/`FileOutputStream` are closed on every exit path (success, HTTP
  error, cancel, IOException) — no leaked file descriptor under repeated prefetch churn (RH5).
- [INV-05] `writeTemp`'s Android-only in-memory-base64 branch no longer exists after this UC
  ships — Android runs the exact same code path iOS already runs for `writeTemp` (A4); a
  regression check confirms no dead code / no residual Android-only branch remains.

## Error Cases

| Error Code | Condition | HTTP Status | Handling |
|---|---|---|---|
| `NON_2XX_ORIGIN` | origin responds with a non-2xx status | (the real origin status, forwarded) | native promise resolves with the real status in the result — `verifyAndPromote`'s existing `OriginStatusRejectedError` classification handles it downstream, unchanged (R3) |
| `CONTENT_LENGTH_MISMATCH` | streamed byte count does not match `Content-Length` | n/a (transport-level) | native promise still resolves/rejects per the streamed outcome; `verifyAndPromote`'s existing Content-Length-match discard governs, unchanged (R3) |
| `STREAM_IO_ERROR` | IOException / socket error mid-stream, or write failure to `destPath` | n/a | native promise rejects; caller's existing catch/discard path handles it (unchanged) |

This UC introduces **no new error codes at the JS boundary** (see [[ux-behavior#Error
Catalog]]) — the rows above name transport-level conditions for Test Surface derivation only;
the caller-visible contract stays exactly what `verifyAndPromote` already enforces.
